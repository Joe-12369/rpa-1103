# 手机模块重构优化记录

> 说明：本文档用于持续记录手机模块的重构与优化点。
> 当前内容先覆盖最近两次提交中已经落地的改动，后续如果还有新的重构点，可以直接在本文档继续补充。

## 一、重构目标

这两次调整围绕两个核心目标展开：

1. 优化 `PageSource` 的更新机制，减少定时轮询带来的并发、卡顿和不稳定问题。
2. 优化 scrcpy 手机界面的内嵌流程，提升窗口重父子句柄、尺寸调整和嵌入稳定性。

---

## 二、优化点汇总

| 优化点 | 原有潜在问题或不足 | 本次调整后的作用 |
|---|---|---|
| `PageSource` 刷新机制从固定定时轮询改为“脏标记 + 单飞刷新 + 熔断” | 过去按固定频率刷新，容易产生并发刷新、接口调用过密、某些页面卡住甚至把 Appium / node 服务打崩的问题 | 降低无意义刷新次数，避免并发刷新叠加，提升页面结构获取的稳定性和可控性 |
| 将 `PageSource` 视为低频快照，而不是高频实时流 | 旧逻辑更像持续实时拉取，导致成本高、压力大，且容易在弱机型或复杂页面上出问题 | 明确了数据职责分层：结构快照负责“可用性”，缓存负责“高频命中” |
| 增加 capture mode 的状态控制 | 拾取时 `Ctrl + 左键` 不应被当成真实手机输入，否则会误触发页面变化和脏刷新 | 让拾取态和真实输入态隔离，减少拾取过程中的误判和误刷新 |
| scrcpy 输入观察从“只看鼠标事件”改为“结合捕获态抑制” | 如果简单把电脑端鼠标动作都当成手机操作，会把拾取自身的交互也算进去，造成结构刷新混乱 | 让输入监测只在真实操作时生效，避免拾取动作污染状态 |
| 手机屏幕内嵌流程增强了窗口句柄校验和重试 | 旧流程更偏一次性执行，`SetParent` / `SetWindowLong` / `MoveWindow` 任何一步不稳都可能导致嵌入失败 | 通过句柄验证、样式重算、重试和失败日志，提升偶现内嵌失败的可定位性和成功率 |
| 窗口样式改为“基于当前样式增量调整” | 之前直接写死样式值，容易覆盖窗口原本已有的有效属性，导致兼容性问题 | 保留原窗口属性，仅补齐内嵌所需样式，降低样式误伤 |
| 窗口 resize 增加 `SetWindowPos` 优先和 `MoveWindow` 兜底 | 单一 resize API 在不同窗口状态下兼容性不一致，容易出现表面成功但尺寸未真正生效的情况 | 提升尺寸调整的鲁棒性，减少嵌入后窗口尺寸不对、显示异常的问题 |
| 在关键动作上增加可观测日志 | 之前只能感知“失败了”，但很难明确失败发生在哪一步 | 可以定位是句柄、父窗口、样式、尺寸更新还是句柄失效导致的问题 |

## 三、PageSource 更新机制优化

### 1. 优化目标

原来的实现更偏向“定时刷新 PageSource”，这种方式在手机自动化场景中容易带来两个问题：

- 刷新频率偏高，造成不必要的 gRPC / Appium 压力。
- 多处同时触发刷新时，存在并发和重入风险，复杂页面下更容易把服务链路拖慢。

### 2. 主要调整

- 将 `PageSource` 定位为结构快照，而不是实时流。
- 引入脏标记机制，只有在页面可能变化时才触发刷新。
- 引入单飞刷新，避免同一时刻重复刷新。
- 引入熔断机制，连续失败后短时间内暂停刷新，避免把故障放大。
- 在拾取前、页面变化后、捕获开始时，按需触发强刷新。

### 3. 带来的作用

- 降低了无意义的 PageSource 拉取次数。
- 避免了高频并发刷新导致的卡顿和崩溃风险。
- 页面结构变化时仍能及时刷新，不再完全依赖固定轮询。
- 整体链路更接近“按需取数、稳定优先”的思路。

### 4. 当前职责划分

- `MobileElementRepository`：负责缓存和元素树。
- `PageSourceRefreshService`：负责刷新策略、脏标记、单飞和熔断。
- `MobileDeviceManager`：负责对外承接和统筹调用。

## 四、手机界面内嵌优化

### 1. 优化目标

内嵌手机屏幕的目标不是单纯“能显示”，而是要尽量避免：

- 偶现内嵌失败。
- 句柄已经拿到，但窗口还没有准备好。
- 父子关系调整后样式未生效。
- 尺寸调整后界面没有真正落地。

### 2. 主要调整

- 将 scrcpy 窗口启动、查找、嵌入、缩放逻辑从视图中拆到独立服务。
- 内嵌前先确认窗口句柄有效。
- `SetParent`、`SetWindowLong`、`SetWindowPos` 都加入失败诊断。
- 窗口样式不再硬编码覆盖，而是基于当前样式做增量调整。
- 内嵌流程增加重试，不因一次瞬时失败就直接判定整个连接失败。
- resize 逻辑从单点调用改为优先稳定 API，再做兼容兜底。

### 3. 带来的作用

- 让“连接成功但内嵌失败”的场景更容易定位。
- 降低了 scrcpy 窗口句柄未完全稳定时的失败概率。
- 减少了样式覆盖导致的兼容性问题。
- 提升了窗口嵌入和窗口调整的一致性。

### 4. 当前职责划分

- `MobileScreenMirrorService`：负责 scrcpy 进程启动、窗口查找、内嵌和调整。
- `Win32Helper`：负责相关 Win32 API 封装。
- `DeviceScreenView`：负责视图层调用和宿主容器承接。

## 五、拾取与捕获态控制

### 1. 背景问题

拾取过程中，用户进入 `Ctrl + 左键` 等捕获动作时，这些动作本身不应该被当成真实手机输入。
如果不区分捕获态和正常操作态，可能会导致：

- 页面被误判为发生变化。
- PageSource 被错误刷新。
- 拾取链路和真实输入链路互相污染。

### 2. 主要调整

- 增加 capture mode 状态控制。
- 捕获开始时强制刷新一次 PageSource。
- 捕获结束时自动恢复普通状态。
- scrcpy 输入监测对捕获态做抑制。

### 3. 带来的作用

- 拾取流程和真实操作流程分离。
- 降低误刷新、误触发、误判页面变化的概率。
- 提升拾取时结构和界面状态的一致性。

## 六、当前实现的模块边界

- `MobileDeviceManager`：对外统一入口，承接页面结构刷新、元素拾取、连接状态控制。
- `MobileElementRepository`：元素缓存和结构树管理。
- `PageSourceRefreshService`：页面结构刷新策略。
- `MobileScreenMirrorService`：scrcpy 窗口相关生命周期。
- `ScrcpyInputMonitor`：输入观察与脏标记触发。
- `DeviceScreenView`：视图侧承接和 UI 调度。
